저를 소개합니다

안녕하세요! 저는 프론트엔드 개발자 김현주입니다. 사용자 중심의 인터페이스를 설계하고 구현하는 것을 좋아합니다. 웹 기술을 활용하여 아이디어를 현실로 만들고, 성능과 접근성을 모두 고려한 제품을 만드는 것이 목표입니다. 새로운 기술을 탐구하고, 더 나은 코드를 작성하기 위해 매일 노력합니다.

단순히 기능을 구현하는 것을 넘어, "왜 이 기능이 필요한가"를 먼저 고민합니다. 사용자의 Pain Point를 발굴하고, UX 씽킹을 기반으로 문제를 정의한 뒤 코드로 해결합니다. 디자인 씽킹 (Desirability · Viability · Feasibility)을 적용해 접근성과 효율성을 모두 갖춘 제품을 만드는 것이 목표입니다.

쇼핑몰 웹사이트
이커머스 플랫폼

팀
개인 프로젝트 (1인)
역할
기획 · UX 플로우 설계 · 풀스택 개발
해결 문제
결제 7단계로 인한 이탈률 70% → 4단계로 축소해 전환율 개선
기술
ReactNode.jsMongoDB
결과
결제 7→4단계, 풀스택 구현 완료
UX Process
리서치→ 와이어프레임→ 사용자 흐름→ 개선과정→ 결과
🔍 리서치

현재: 장바구니→결제 7단계, 이탈률 약 70%. 사용자 피드백에서 "구매 과정이 복잡하다" 의견 다수.

목표: 결제 4단계 이하, 이탈률 20%p 감소. 비즈니스: 전환율·구매 완료율 향상.

📐 와이어프레임

결제 플로우 중심으로 화면 구조 설계. 상품 목록·상세·장바구니·결제(4단계) 정보 구조 정의. 불필요한 중간 단계 제거한 IA 구성.

🗺️ 사용자 흐름

진입 → 상품 탐색 → 상세 확인 → 장바구니 추가 → 결제(4단계). 장바구니·결제·주문 관리를 하나의 흐름으로 통합, 단계별 이탈 포인트 최소화.

🔄 개선과정

기존 7단계 결제를 페이지 통합·입력 항목 그룹화로 4단계로 축소. 주문 확인 단계를 결제 화면 내 인라인으로 포함해 클릭 수 감소.

📊 결과
7 → 4단계결제 단계
풀스택프론트+백엔드

#02 웹 · UX

할 일 관리 웹
생산성 앱

팀
개인 프로젝트 (1인)
역할
UI 설계 · 프론트엔드 개발
해결 문제
새로고침 시 데이터 유실 100% → LocalStorage로 유실 0건
기술
ReactCSS3LocalStorage
결과
데이터 유실 0건, 할 일 추가 2클릭
UX Process
리서치→ 와이어프레임→ 사용자 흐름→ 개선과정→ 결과
🔍 리서치

현재: 새로고침 시 할 일 유실 100%, 완료/미완료 구분 불명확. "추가했다가 잊어버린다" 페인포인트 다수.

목표: 데이터 유실 0건, 할 일 추가 2클릭 이내. 상태 시각 구분으로 인지 부담 감소.

📐 와이어프레임

단일 리스트 + 입력 영역 구조. 완료/미완료 시각 구분(체크·취소선)·필터 탭 설계. 최소 화면으로 추가·수정·삭제 가능하도록 IA 정의.

🗺️ 사용자 흐름

진입 → 할 일 입력(1~2클릭) → 목록 확인/완료 토글 → (선택) 수정·삭제. 새로고침 후에도 동일 화면 유지되도록 영속 경로 설계.

🔄 개선과정

LocalStorage 연동으로 데이터 유실 0건 달성. 완료/미완료 색상·아이콘으로 명확히 구분. 입력 후 즉시 리스트 반영되도록 플로우 단순화.

📊 결과
0건데이터 유실
2클릭할 일 추가

#03 웹 · UX

날씨 대시보드
실시간 정보 시각화

팀
개인 프로젝트 (1인)
역할
정보 구조 설계 · 프론트엔드 개발
해결 문제
핵심 날씨 확인 10초+ → 1초 이내 인지, 위치 자동 조회
기술
JavaScriptCSSOpenWeather API
결과
1초 이내 핵심 확인, 입력 없이 위치 자동
UX Process
리서치→ 와이어프레임→ 사용자 흐름→ 개선과정→ 결과
🔍 리서치

현재: 기존 앱 정보 과부하로 핵심 날씨 확인 10초+. "기온·체감온도 한눈에 보고 싶다" 니즈 확인.

목표: 진입 후 1초 이내 핵심 정보 인지. 위치 자동 조회로 입력 단계 제거.

📐 와이어프레임

단일 뷰에 기온·날씨·체감온도 최상위 배치. 보조 정보(습도·풍속 등)는 하위 계층. 위치 기반 1화면 구조로 정보 계층 설계.

🗺️ 사용자 흐름

진입(위치 자동) → 즉시 현재 날씨 확인. 별도 검색/설정 없이 한 화면에서 핵심 정보만 노출. 스크롤 최소화.

🔄 개선과정

OpenWeather API로 위치 기반 자동 조회 적용. 시각적 위계(타이포·색상)로 기온·체감·날씨 상태를 1초 내 인지 가능하도록 개선.

위치 자동입력 없이 조회

#04 웹 · UX

모아
취미 공유 플랫폼

팀
팀 프로젝트 (4명)
역할
모임 리스트·상세 페이지 담당
해결 문제
탐색 9분·이탈 40% → 6분·이탈 10%p↓
기술
Next.jsZustandFigma
결과
9→6분, 33% 단축, 이탈 10%↓
UX Process
리서치→ 와이어프레임→ 사용자 흐름→ 개선과정→ 결과
🔍 리서치

현재: 취미 모임 탐색 시 평균 클릭 9회, 9분 소요, 이탈률 약 40%. 사용자 인터뷰 5명—"원하는 모임 찾기까지 너무 오래 걸린다" 공통.

목표: 탐색 6분 이하(33% 단축), 이탈률 10%p 감소. 비즈니스: 모임 참여율·가입 전환 향상.

📐 와이어프레임

Figma로 메인·탐색·모임 상세·가입·참여 화면 설계. 탐색→가입→참여 3단계 IA. 카테고리·필터 노출로 클릭 수 감소 구조.

🗺️ 사용자 흐름

진입 → 카테고리/필터로 탐색 → 모임 상세 → 가입 → 참여. 기존 9회 클릭을 5단계 이내로 재설계. 프로토타입으로 사용성 테스트 진행.

🔄 개선과정

테스트 피드백 반영—탐색 경로 단축·CTA 배치 조정. 모임 찾기 9분→6분, 이탈률 약 10%p 감소. 반복 개선 후 개발 연동.

📊 결과
9→6분탐색 시간
33%단축
10%↓이탈률

역할
OAuth 로그인·글쓰기·등록 담당
해결 문제
글 찾기 3분+ → 태그·검색으로 30초 이내
기술
JavaScriptTypeScriptOAuthHTML/CSS
결과
태그+검색 2경로, CRUD
UX Process
리서치→ 와이어프레임→ 사용자 흐름→ 개선과정→ 결과
🔍 리서치

현재: 태그·검색 부재로 원하는 글 찾기 3분+, 주제별 모아보기 불가. 독자 "관심 주제만" / 작성자 "글 분류 직접 관리" 니즈 발굴.

목표: 태그·검색으로 목표 글 30초 이내, 2가지 탐색 경로. 비즈니스: 체류·재방문 증가.

📐 와이어프레임

Figma 스토리 기반 IA. 목록·태그 필터·검색·글 상세·작성/수정 화면 설계. 독자(읽기)와 작성자(쓰기) 플로우 분리한 구조.

🗺️ 사용자 흐름

독자: 진입 → 태그/검색으로 탐색 → 글 열기. 작성자: 글 쓰기 → 태그 지정 → 발행·수정·삭제. 두 페르소나별 경로 명확화.

🔄 개선과정

태그 기반 필터 + 검색 기능 도입으로 탐색 경로 2가지 제공. 목표 글 도달 30초 이내 설계. CRUD(작성·수정·삭제) 플로우 구현·검증.

태그+검색2경로
30초 이내목표 도달
CRUD글 관리
